## 1. 프로젝트 개요

TICK은 이용자가 가상 계좌의 자산을 확인하고 주식을 매수·매도하며, 주문·체결 결과와 실시간 시세를 확인하는 증권 거래 플랫폼이다. 주문을 받은 뒤 거래가 성립하고 자산이 반영되는 전체 과정을 제공하며, 많은 요청이 동시에 발생하거나 서비스가 중단되는 상황에서도 거래 결과를 일관되게 유지한다.

프로젝트는 다음 세 가지 결과를 목표로 한다.

1. **정확한 거래** — 같은 계좌에서 주문이 동시에 발생해도 사용할 수 있는 자산을 초과해 주문하지 않으며, 체결과 취소 결과가 계좌에 정확히 반영된다.
2. **대규모 실시간 시세 제공** — 이용자는 관심 종목의 시세를 지속적으로 확인할 수 있으며, 대량 구독 상황에서도 최신 정보를 전달받는다.
3. **장애와 배포 중 거래 보존** — 접수가 확정된 주문과 확정된 체결은 서비스 재시작이나 배포 후에도 유지되며, 진행 중인 주문의 결과를 다시 확인할 수 있다.

| 주요 목표 | 요구되는 결과 | 현재 정의 수준 |
| --- | --- | --- |
| 동일 계좌 동시 주문 | 자산 초과 사용 및 중복 반영 없음 | 필수 요구사항 |
| 주문·체결 복구 | 접수 확정 주문과 확정 체결 유실 없음 | 필수 요구사항 |
| 주문 10,000건/초 | 유효한 주문 부하를 안정적으로 처리 | 목표 수치 확정, 시험 조건 미정 |
| 동시 시세 구독자 100,000명 | 구독 중인 이용자에게 시세 갱신 전달 | 목표 수치 확정, 시험 조건 미정 |
| 배포 중 주문 보존 | 진행 중인 주문과 체결 이력 유지 | 필수 요구사항 |

본문의 기능과 품질 요구사항은 검토할 요구사항이다. 사용자가 아직 지정하지 않은 거래 정책은 **초안 정책**으로, 판단에 필요한 정보가 없는 항목은 **미정**으로 표시한다. 목표 수치는 달성한 성능을 의미하지 않는다.

### 2.1 대상 사용자

| 대상 | 원하는 일 | 확인할 수 있어야 하는 결과 |

| 서비스 운영자 | 처리 지연·오류·연결 이상을 발견하고 거래 이력을 확인 | 처리 현황, 이상 발생 범위, 주문별 진행 상황, 복구 결과 |
| 검증 담당자 | 동시 주문·대량 구독·장애 상황에서 서비스 요구사항 확인 | 재현 조건, 실제 처리 결과, 정합성 검증 결과, 성능 측정치 |

계좌·주문·체결 정보는 접근 권한을 가진 사용자에게 제공한다. 사용자 가입과 본인 확인의 구체적인 범위는 D-10에서 결정한다.

여기서 가상 시장은 실제 거래소를 대신해 주문을 받아 체결 결과와 시세를 제공하는 업무 역할이다. 각 역할을 어떤 프로그램이나 서버로 구성할지는 본 문서에서 정하지 않는다.

### 2.3 범위에서 제외하는 항목 초안

- 실제 자금의 입출금·수탁, 실제 증권 계좌 개설, 실제 거래소 주문 전송
- 실제 한국거래소의 전체 거래 제도와 전문 규격 재현
- 신용 거래·공매도·파생상품 거래
- 투자 추천·투자 자문·수익률 예측
- 법정 세금 신고 및 실제 결제기관을 통한 결제

위 제외 범위는 모의 거래 프로젝트라는 전제에 따른 초안이다. 수수료·세금을 모의 자산에 반영할지는 별도 정책으로 결정한다. 이용자 화면의 시각 디자인과 구체적인 조작 방식은 본 요구사항을 바탕으로 후속 기획에서 정의한다.

## 3. 주요 이용 시나리오

### 3.1 매수 주문과 체결

1. 이용자가 계좌의 보유 현금과 주문 가능 금액을 확인한다.
2. 종목, 매수 구분, 가격 조건, 수량을 지정해 주문한다.
3. 서비스가 요청 조건과 가용 자산을 확인하고 접수 확정 또는 거절 결과를 알린다.
4. 접수가 확정된 주문은 가상 시장에서 체결 가능한 상대 주문을 기다린다.
5. 주문의 전부 또는 일부가 체결되면 체결 가격·수량·시각과 남은 수량을 확인할 수 있다.
6. 체결 결과와 관련된 현금·주식 변동이 계좌에 반영된다.

**이용자가 구분해야 할 결과:** 요청을 보냈다는 사실, 접수 확정 여부, 실제 체결 여부는 서로 다른 정보다. 접수가 확정되었다는 응답을 체결 완료로 안내해서는 안 된다.

### 3.2 매도 주문과 부분 체결 후 취소

1. 이용자가 보유 주식과 매도 가능 수량을 확인한다.
2. 보유한 종목의 매도 주문을 제출한다.
3. 일부 수량이 체결되면 누적 체결량과 남은 수량을 확인한다.
4. 이용자가 남은 수량의 취소를 요청한다.
5. 취소 처리 시점까지 발생한 체결은 유지하고, 취소가 확정된 수량은 더 이상 체결되지 않는다.
6. 매도 대금과 남은 주식 수량, 취소로 다시 사용할 수 있게 된 주식 수량을 확인한다.

**이용자가 구분해야 할 결과:** 취소 요청 접수는 취소 확정을 의미하지 않는다. 취소 처리와 체결이 겹치면 최종 체결량과 취소 확정량을 안내한다.

### 3.3 응답을 받지 못한 주문 확인

1. 이용자가 주문했으나 연결 중단 등의 이유로 접수 결과를 받지 못한다.
2. 이용자는 같은 주문 의도를 다시 전달하거나 기존 요청의 처리 결과를 확인한다.
3. 서비스는 기존 요청과의 관계를 확인해 새로운 주문이 중복 생성되지 않도록 한다.
4. 처리 여부를 확인하는 동안에는 확인 중임을 알리고, 최종 접수·거절·체결 결과를 확인할 수 있게 한다.

응답을 받지 못했다는 이유만으로 미접수 또는 주문 실패로 표시해서는 안 된다.

### 3.4 종목 시세 구독과 재연결

1. 이용자가 종목의 현재가와 호가를 조회한다.
2. 관심 종목의 실시간 구독을 시작한다.
3. 현재 상태를 확인하고 이후 발생하는 해당 종목의 갱신을 전달받는다.
4. 연결이 끊기거나 시세 갱신의 누락이 발견되면 정보가 최신이 아닐 수 있음을 확인할 수 있다.
5. 재연결 후 구독을 복원하고 최신 상태부터 시세 확인을 이어간다.
6. 필요 없는 종목은 구독을 해제한다.

## 4. 거래 업무 규칙

### 4.1 주문과 자산

| 규칙 ID | 업무 규칙 |
| --- | --- |
| BR-01 | 주문은 계좌, 종목, 매수·매도 구분, 주문 조건, 원주문 수량을 구분할 수 있어야 한다. |
| BR-02 | 매수 주문 접수가 확정되면 해당 주문에 필요한 현금을 다른 주문에 중복 사용할 수 없어야 한다. |
| BR-03 | 매도 주문 접수가 확정되면 해당 주문의 주식 수량을 다른 매도 주문에 중복 사용할 수 없어야 한다. |
| BR-04 | 주문 가능 현금과 주문 가능 주식 수량은 음수가 될 수 없다. 주문 검증과 자산 반영이 동시에 발생해도 이 규칙을 유지한다. |
| BR-05 | 체결된 수량에 대해서만 매수자의 현금·주식과 매도자의 현금·주식에 거래 결과를 반영한다. 미체결 수량을 체결로 계산하지 않는다. |
| BR-06 | 취소가 확정되거나 주문이 거절되어 더 이상 필요하지 않은 자산 예약은 해제한다. 체결 반영에 필요한 예약은 체결 처리와 일치하게 반영한다. |
| BR-07 | 하나의 주문 의도가 여러 번 전달되어도 하나의 주문으로 처리한다. 같은 조건으로 별개의 주문을 낸 경우와는 구분할 수 있어야 한다. |
| BR-08 | 하나의 체결 결과가 여러 번 전달되거나 복구 과정에서 다시 확인되어도 계좌에는 한 번만 반영한다. |

‘예약’은 접수된 주문 때문에 다른 주문에서 사용할 수 없는 자산을 뜻한다. 이를 관리하는 저장 방식이나 처리 방법을 의미하지 않는다.

### 4.2 수량과 체결

접수가 확정된 주문은 처리 전 과정에서 다음 관계를 만족해야 한다.

**원주문 수량 = 누적 체결 수량 + 취소 확정 수량 + 유효한 미체결 잔량**

- 원주문 수량보다 많이 체결될 수 없다.
- 동일한 수량을 체결과 취소에 동시에 포함할 수 없다.
- 취소 확정된 수량은 이후 체결할 수 없다.
- 부분 체결 이후 잔량이 취소되어도 이미 확정된 체결은 유지한다.
- 같은 거래의 매수 측과 매도 측은 종목, 체결 수량, 체결 가격이 일치해야 한다.
- 거래에 따른 자산 변화는 양측 체결 내역과 일치해야 한다. 초기 자산 지급, 수수료, 세금 등 별도 증감은 거래 변동과 구분해 설명할 수 있어야 한다.

### 4.3 초기 거래 정책 초안

| 정책 | 초안 | 확정 상태 |
| --- | --- | --- |
| 주문 유형 | 지정가 매수·매도 지원 | 제공 백로그에 근거한 초기 범위, 추가 유형은 D-01 |
| 매칭 우선순위 | 유리한 가격 우선, 같은 가격에서는 먼저 접수된 주문 우선 | 제공 백로그에 근거한 규칙, 동순위 기준은 D-02 |
| 체결 가격 | 매수·매도 양측의 지정가 조건을 만족해야 함 | 구체적인 가격 결정 규칙은 D-02 |
| 주문 취소 | 미체결 잔량 전체 취소 | 부분 수량 취소 지원 여부는 D-03 |
| 주문 정정 | 초기 범위에 포함하지 않음 | 초안, D-03에서 확정 |
| 수량·금액 단위 | 양의 정수 수량, 허용된 가격 단위 사용 | 거래 단위와 가격 단위는 D-04 |
| 수수료·세금 | 적용 여부 미정 | D-05 |

초안 정책은 실제 거래소의 모든 규칙을 재현한다는 의미가 아니다. 정책이 확정되면 해당 정책을 적용한 구체적인 예시로 인수 조건을 보완한다.

### 4.4 이용자에게 제공할 주문 상태

| 상태 또는 결과 | 의미 | 이용자에게 제공할 정보 |
| --- | --- | --- |
| 요청 확인 중 | 요청 처리 여부가 아직 확정되지 않았거나 이용자가 최종 응답을 받지 못함 | 확인 중이라는 사실과 결과를 다시 확인하는 방법 |

| 미체결 대기 | 접수된 주문의 유효 잔량이 체결을 기다림 | 주문 조건과 미체결 잔량 |
| 부분 체결 | 원주문 수량의 일부가 체결되고 유효 잔량이 남음 | 누적 체결량, 체결 내역, 미체결 잔량 |
| 전량 체결 | 원주문 수량이 모두 체결됨 | 전체 체결 내역과 최종 자산 반영 결과 |
| 잔량 취소 확정 | 남아 있던 수량의 취소가 확정됨 | 기존 체결량, 취소 확정량, 최종 유효 잔량 |
| 접수 거절 | 요청이 거래 조건을 충족하지 못해 접수가 거절됨 | 거절 사유와 접수되지 않았다는 결과 |

이 표는 이용자에게 구분해서 알려야 할 업무 결과다. 내부 상태 이름과 상태 저장 구조는 별도 설계에서 정한다. 취소 처리 중임을 주문의 체결 상태와 함께 표시할 수 있어야 한다.

### 6.2 주문 처리 목표

**목표: 초당 10,000건의 주문이 발생하는 상황에서 안정적으로 주문을 처리한다.**

측정 대상의 초안은 충분한 자산을 보유한 계좌가 제출한 유효 주문의 **접수 확정 처리량**이다. 주문 접수와 실제 체결 처리량은 별도로 기록한다. 가용 자산 부족이나 잘못된 요청을 대량 거절한 결과를 정상 주문 처리량으로 대신하지 않는다.

| 반드시 기록할 항목 | 내용 |
| --- | --- |
| 부하 구성 | 매수·매도·취소 비율, 종목 수, 계좌 수, 동일 계좌 및 특정 종목 집중도 |
| 시험 지속 시간 | 목표 부하 유지 시간, 부하 증가·감소 과정 |
| 처리 결과 | 제출량, 접수 확정량, 업무상 거절량, 시스템 오류량, 결과 미확정량 |
| 지연 | 제출부터 접수 결과 확정까지의 평균·P95·P99·최대 지연, 접수부터 체결·자산 반영까지의 지연 |
| 거래 정확성 | 시험 종료·후속 처리 후 주문 수량 관계, 현금·주식·예약 자산 정합성 |
| 시험 환경 | 사용한 처리 자원, 네트워크 조건, 부하 발생 환경 |

시험 지속 시간, 허용 오류율, 접수 지연 상한과 결과 미확정 허용 시간을 D-06에서 확정한다. 이 값들이 비어 있는 동안에는 목표 달성 판정을 보류한다.

### 6.3 실시간 시세 구독 목표

**목표: 100,000명이 동시에 종목 시세를 구독하고 실제 갱신을 전달받을 수 있다.**

연결만 유지하는 시험과 시세를 실제로 전달하는 시험을 구분한다. ‘100,000명 구독’ 목표는 활성 구독자에게 시세가 발생하고 전달되는 조건으로 검증한다.

| 반드시 기록할 항목 | 내용 |
| --- | --- |
| 구독 구성 | 전체 활성 구독자 수, 이용자별 구독 종목 수, 종목별 집중도 |
| 시세 구성 | 종목 수, 초당 갱신 수, 전달 정보의 크기, 체결가·호가 비율 |
| 전달 결과 | 연결 유지 수, 정상 수신 수, 지연·미수신·재연결 수, 전달 갱신 수 |
| 지연 | 시세 생성·수신·이용자 도달 사이의 구간별 지연과 전체 지연의 평균·P95·P99·최댓값 |
| 자원 사용량 | CPU, 메모리, 네트워크 사용량과 활성 구독자 수의 관계 |
| 불리한 상황 | 한 종목 집중 구독, 느린 이용자, 연결 종료 후 재접속 집중 |

주문 목표와 시세 구독 목표를 같은 시간에 동시에 만족해야 하는지는 D-09에서 결정한다. 시세 갱신 빈도·구독 분포·지연 기준은 D-07에서 확정한다.

### 6.4 장애와 운영 연속성

장애와 배포 검증에서는 데이터 보존 여부와 이용 가능 상태 회복 시간을 각각 확인한다. 최소한 다음 시점을 포함한다.

- 주문 요청을 받았으나 접수 결과를 이용자에게 알리기 전
- 접수 확정을 알린 뒤 가상 시장에서 처리되기 전
- 부분 체결이 발생한 뒤 나머지 수량을 기다리는 중
- 체결이 확정되었으나 관련 조회 결과가 모두 갱신되기 전
- 취소 요청과 체결이 함께 진행되는 중
- 시세 구독자가 연결을 유지하는 중

장애가 해소된 뒤 주문·체결·자산 상태를 확인해 미완료 처리를 이어갈 수 있어야 한다. 배포 중에는 신규 주문 접수와 주문 결과 확인을 계속 제공한다. 복구 시간 목표와 배포 중 지연·오류 허용 기준, 시세 연결의 연속성 범위는 D-11·D-12에서 결정한다.

## 7. 대표 인수 시나리오

아래 사례는 기획 요구사항의 완료를 확인하는 기준이다. 거래 정책이 미정인 사례는 해당 정책 확정 후 기대 가격·시간 기준을 추가한다.

### AT-01 같은 계좌의 동시 매수

- **준비:** 가용 현금 1,000,000원, 기존 예약 없음. 각 요청은 정확히 100,000원을 예약하며 서로 다른 주문 의도다. 시험 중 체결·취소·입출금·수수료·시스템 장애는 없다.
- **행동:** 같은 계좌에 1,000건을 동시에 제출한다.
- **기대:** 정확히 10건이 접수 확정되고 나머지는 가용 자산 부족으로 거절된다. 예약 합계는 1,000,000원, 남은 가용 현금은 0원이다.
- **관련:** AC-02, OR-02, NQ-01

### AT-02 같은 계좌의 동시 매도

- **준비:** 특정 종목 100주 보유, 기존 예약 없음. 각 요청은 10주 매도이며 시험 중 체결·취소·자산 변동·시스템 장애는 없다.
- **행동:** 서로 다른 주문 의도로 100건을 동시에 제출한다.
- **기대:** 정확히 10건이 접수 확정된다. 예약 수량은 100주를 넘지 않고 남은 매도 가능 수량은 0주다.
- **관련:** AC-02, OR-02, NQ-01

### AT-03 부분 체결 후 잔량 취소

- **준비:** 100주 주문 중 40주 체결, 다른 체결 없음.
- **행동:** 유효 잔량의 취소를 요청하고 최종 결과를 확인한다.
- **기대:** 누적 체결 40주, 취소 확정 60주, 유효 잔량 0주다. 40주의 체결 효과는 유지되며 취소된 60주의 예약 자산은 다시 사용할 수 있다.
- **관련:** EX-03, CA-01, CA-03

### AT-04 취소 요청과 체결의 경합

- **준비:** 일부 또는 전부가 미체결 상태인 주문이 있다.
- **행동:** 잔량의 취소 요청과 해당 주문을 체결시킬 수 있는 상대 주문을 함께 발생시킨다.
- **기대:** 최종 체결량·취소량·잔량의 합이 원수량과 같다. 취소 확정된 수량의 사후 체결 및 체결·취소 이중 계산이 없다. 계좌 결과가 최종 수량과 일치한다.
- **관련:** CA-02, NQ-01

### AT-05 응답 유실 후 같은 주문 재요청

- **준비:** 한 주문의 접수 응답이 이용자에게 도달하지 않는다.
- **행동:** 동일 주문 의도를 다시 제출하고 기존 처리 결과를 확인한다.
- **기대:** 같은 의도의 주문은 최대 하나만 존재하고 예약도 한 번만 반영된다. 별개의 새 주문으로 제출한 요청은 따로 처리한다.
- **관련:** OR-04, RC-03

### AT-06 주문과 체결 처리 도중 종료

- **준비:** 접수 확정 주문, 부분 체결 주문, 취소 처리 중 주문을 포함한다.
- **행동:** 6.4의 각 처리 시점에 서비스를 종료한 후 재가동한다.
- **기대:** 접수 확정 주문과 확정 체결이 보존된다. 유효 미체결 주문의 조건·순서·잔량과 자산 예약을 복구한다. 체결 결과를 다시 확인해도 자산이 중복 반영되지 않는다.
- **관련:** RC-01, RC-02, NQ-02

### AT-07 매칭 우선순위

- **준비:** 가격이 다른 주문과 같은 가격에서 접수 순서가 다른 주문을 준비한다.
- **행동:** 체결 가능한 상대 주문을 제출한다.
- **기대:** 합의된 가격·접수 순서 우선순위에 따라 체결한다. 모든 체결 가격은 양측 주문 조건을 만족한다. 동순위와 체결 가격은 D-02 확정 후 구체적인 예시로 검증한다.
- **관련:** EX-01, EX-02

### AT-08 시세 구독 시작과 중단 후 복구

- **준비:** 갱신이 계속 발생하는 종목을 구독한다.
- **행동:** 구독 시작 시점에 시세를 변경하고, 구독 중 연결 단절과 갱신 누락을 각각 발생시킨 뒤 복구한다.
- **기대:** 현재 상태와 갱신을 일관되게 이어받는다. 이상 상태가 감지되며 복구 후 최신 체결가·호가가 가상 시장의 기준 상태와 일치한다.
- **관련:** MD-03, MD-04, MD-05

### AT-09 느린 구독자와 재접속 집중

- **준비:** 정상 수신자와 느린 수신자를 함께 포함한다.
- **행동:** 일부 이용자의 수신을 지연시키고 다수 이용자가 연결을 끊었다가 다시 접속하게 한다.
- **기대:** 정상 이용자의 시세 수신이 계속되며 지연·오류·자원 사용량을 확인한다. D-07에서 합의한 영향 허용 기준을 만족한다.
- **관련:** MD-06, OP-02, NQ-03

### AT-10 대량 주문과 활성 시세 구독

- **준비:** D-06·D-07에서 합의한 시험 조건을 사용한다.
- **행동:** 주문 10,000건/초 및 활성 시세 구독자 100,000명 조건을 각각 유지한다. 동시 검증 여부는 D-09에 따른다.
- **기대:** 합의한 유지 시간·오류율·지연 기준을 만족하며 시험 전후 거래 정합성과 최신 시세 복구 가능 여부가 일치한다. 실제 처리량과 환경을 함께 제시한다.
- **관련:** 6.2, 6.3, NQ-01, NQ-02

### AT-11 진행 중 주문이 있는 배포

- **준비:** 신규 접수, 미체결, 부분 체결, 취소 처리 중 주문을 포함한다.
- **행동:** 주문·체결이 진행되는 동안 새 버전을 배포한다.
- **기대:** 배포 중에도 신규 주문을 접수하고 주문 결과를 확인할 수 있다. 기존 주문과 확정 체결의 유실·중복이 없다. 배포 중 접수의 성공·지연·오류는 D-12의 기준으로 판정한다.
- **관련:** RC-04, NQ-02

## 10. 용어

| 용어 | 의미 |
| --- | --- |
| 가용 자산 | 새로운 주문에 사용할 수 있는 현금 또는 주식 수량 |
| 예약 자산 | 접수된 주문 때문에 다른 주문에서 사용할 수 없는 현금 또는 주식 수량 |
| 접수 확정 | 주문 검증을 통과해 서비스가 주문으로 받아들였음이 확정된 상태 |
| 체결 확정 | 양측 주문 사이에 거래가 성립한 결과가 확정된 상태 |
| 유효 잔량 | 체결되지 않았고 취소도 확정되지 않아 이후 체결 대상이 될 수 있는 수량 |
| 부분 체결 | 한 주문의 일부 수량만 거래가 성립한 상태 |
| 호가 | 거래를 기다리는 매수·매도 주문의 가격과 수량 정보 |
| 활성 구독자 | 종목을 구독하고 발생하는 시세 갱신을 실제로 전달받는 이용자 |
| 결과 확인 중 | 요청의 최종 처리 결과가 아직 확인되지 않아 재확인이 필요한 상태 |
| P95와 P99 지연 | 측정 요청의 95%와 99%가 각각 그 값 이하의 시간에 처리되었음을 나타내는 지연 지표 |
