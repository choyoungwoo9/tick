# TICK 프론트엔드 목 화면

[`docs/TICK_서비스기획서.md`](../docs/TICK_서비스기획서.md)를 확인하기 위한 화면 초안입니다. 계좌 관리 화면은 백엔드 계좌 API를 사용하고, 주문·자산·시세 화면은 예시 데이터를 사용합니다. React와 TypeScript로 작성했고 Vite로 실행·빌드합니다. 외부 이미지·글꼴이나 CDN이 필요하지 않습니다.

## 실행

Node.js 20.19 이상 또는 22.12 이상을 권장합니다.

```bash
cd frontend
npm install
npm run dev
```

계좌 API를 사용하려면 레포지토리 루트에서 DB와 백엔드를 먼저 실행합니다.

```bash
docker compose up -d --wait
cd backend && ./gradlew bootRun
```

터미널에 표시되는 로컬 주소를 엽니다. 기본 주소는 `http://127.0.0.1:5173`입니다. 다른 프로세스가 포트를 사용하면 Vite가 다른 주소를 안내합니다.

```bash
npm run build
npm run preview
```

`build`는 타입 확인과 정적 파일 생성을 수행합니다. 결과는 `dist`에 만들어집니다. 브라우저에서 계좌 화면을 사용하려면 백엔드 API가 실행 중이어야 합니다. 개발 서버는 `/api` 요청을 `http://localhost:8080`으로 전달합니다.

API 주소와 개발용 사용자 ID는 환경 변수로 바꿀 수 있습니다. 기본값은 `VITE_API_BASE_URL=/api`, `VITE_DEMO_OWNER_ID=1`입니다. 실제 인증은 연결하지 않았으며, `X-Owner-Id` 헤더는 개발용 모의 사용자 식별자입니다.

예시 환경 파일을 복사해 값을 변경할 수 있습니다.

```bash
cp .env.example .env.local
```

## 화면

| 화면 | 주요 구성 | 기획서 대응 |
| --- | --- | --- |
| 내 계좌 `#/assets` | 보유자산, 주문 가능 현금, 예약 현금, 보유 종목, 최근 주문 | AC-01~03 |
| 계좌 관리 `#/accounts` | 계좌 개설, 모의 입금·출금, 잔고·입출금 내역, 출금 두 건 요청 시연 | 계좌·입출금 첫 사용자 스토리 |
| 주문하기 `#/trade` | 종목 선택, 가격 추이, 호가, 매수·매도 입력, 주문 확인창 | OR-01~04, EX-01~03의 화면 진입점 |
| 주문·체결 `#/orders` | 상태별 조회, 주문 상세, 체결 내역, 체결별 자산 변동 | OR-05, EX-03~05, CA-01~03 |
| 시세·관심종목 `#/market` | 검색, 관심종목, 시세 구독, 재연결·시세 지연 안내 | MD-01~06의 상태 표현 |
| 운영 현황 `#/operations` | 처리 지표 예시, 처리 기록, 복구 상태 진입점 | OP-01~03, RC-01~04의 안내 화면 |
| 컴포넌트 모음 `#/components` | 버튼, 상태 배지, 입력, 탭, 안내, 모달, 빈 화면, 스켈레톤 | 공통 UI |

위 대응은 요구사항을 검토할 **화면의 위치**입니다. 거래 정합성, 매칭, 장애 복구, 성능 목표의 구현 또는 검증 완료를 뜻하지 않습니다.

## 확인할 수 있는 상호작용

- 종목 검색, 관심종목 추가·해제, 시세 구독·해제
- 호가 선택 시 주문 가격 입력, 매수·매도 전환, 수량 선택
- 가격·수량 입력 확인, 가용 현금·수량을 이용한 간단한 목 입력 검증
- 주문 확인창을 거쳐 목 주문 목록에 항목 추가
- 주문 입력 하단의 **접수 결과 미리보기**에서 다음 응답을 접수 확정·접수 거절·결과 확인 중으로 선택
- 주문 상세에서 원수량·체결량·취소량·유효 잔량과 여러 체결 내역 확인
- 미체결 잔량 취소 확인과 예약분 해제 예시
- 결과 확인 중 주문의 기존 접수 결과 재확인 예시
- 상단 **목 화면 상태**에서 기본·빈 화면·불러오는 중·오류 상태 전환
- 시세 화면의 **연결 상태 예시**에서 재연결 중·시세 지연 상태 전환
- **목 데이터 초기화**로 주문·자산 등 브라우저 예시 데이터를 복원

## 계좌 개설과 입출금 사용법

새 **계좌 관리** 화면은 백엔드 API와 DB에 저장되는 모의 계좌를 사용합니다. 계좌 이름·번호·잔고·입출금 내역은 새로고침 후에도 유지됩니다. 기존 자산·주문·체결·시세 화면은 계속 예시 데이터를 사용합니다. 새로 개설한 계좌를 주식 주문에 연결하는 기능은 포함하지 않습니다.

1. 왼쪽 메뉴의 **계좌 관리** 또는 `#/accounts`로 이동합니다.
2. **모의 계좌 개설**을 눌러 계좌 이름을 지정합니다. 새 계좌는 **0원**으로 개설됩니다.
3. **입금**을 선택해 금액을 입력하고 확인합니다. 현재 잔고와 입출금 내역에 함께 반영됩니다.
4. **출금**을 선택해 같은 과정을 진행합니다. 잔고를 초과하거나 유효하지 않은 금액을 입력하면 안내됩니다.
5. 내역에서 전체·입금·출금을 구분하고 각 거래 후 잔고를 확인합니다. 거절된 요청은 성공한 입출금 내역에 기록되지 않습니다.
6. 여러 계좌를 만들었다면 상단 선택 계좌를 변경합니다. 계좌별 잔고와 내역은 독립적으로 유지됩니다.

계좌와 거래 내역은 서비스 DB에 저장됩니다. 상단 **목 데이터 초기화**는 브라우저의 주문·자산 예시 데이터만 초기화하며, 서버 계좌는 삭제하지 않습니다.

### 출금 두 건 요청 시연

- 잔고 0원의 새 계좌에 **1,000,000원**을 입금합니다.
- **출금 두 건 요청 시나리오**를 펼칩니다.
- 요청당 금액을 **700,000원**으로 두고 **출금 2건 함께 요청**을 누릅니다.
- 첫 요청은 성공하고 다음 요청은 잔고 부족으로 거절됩니다. 최종 잔고는 **300,000원**이며 성공한 출금 한 건만 내역에 추가됩니다.

이 시연은 서버에 출금 요청 두 건을 순서대로 전송합니다. 실제 병렬 요청, DB 동시성, 다중 브라우저 간 동시성 보장을 검증한 결과는 아닙니다.

### 계좌 화면과 API 클라이언트 테스트

```bash
npm test
```

API 클라이언트가 모의 사용자 헤더와 요청 본문을 전송하고 서버 오류 코드를 보존하는지, 화면이 잘못된 금액을 차단하는지 확인합니다. 서버와 DB까지 포함한 계좌 API 테스트는 `cd backend && ./gradlew test`로 실행합니다. 두 테스트 모두 기존 Node.js와 Gradle 도구를 사용합니다.

계좌 API는 개발용 `X-Owner-Id` 헤더로 소유자를 구분하며 실제 로그인·인증은 연결되어 있지 않습니다. 주문 전송, 자동 매칭, 실시간 시세 전송도 연결되어 있지 않습니다. 취소 처리 중 경합이나 응답 재처리 등의 서버 동작도 재현하지 않습니다.

수수료·세금·실제 거래소 호가 단위는 적용하지 않았습니다. 가격, 거래량, 차트, 운영 지표는 모두 예시입니다. 운영 화면의 숫자는 실제 성능 측정 결과가 아닙니다.

## 구조

```text
src/
  components/
    ui.tsx          공통 버튼·표 래퍼·배지·탭·모달·상태 UI
    charts.tsx      외부 라이브러리 없는 예시 SVG 차트
    trading.tsx     주문 표와 주문·취소 상세 화면
  mocks/data.ts     목 데이터와 화면용 타입
  banking-model.ts  계좌 화면 타입과 입력 금액 검증 규칙
  api/account-api.ts 계좌 백엔드 HTTP 요청·응답 형식
  pages/            계좌·주문·내역·시세·운영·컴포넌트 화면
  context.tsx       주문·자산 화면의 브라우저 목 상태
  banking-context.tsx  계좌 API 조회·개설·입출금 상태
  App.tsx           공통 레이아웃과 화면 이동
  styles.css        공통 스타일과 반응형 레이아웃
```

주문·자산 화면은 아직 `context.tsx`의 목 동작을 사용합니다. 계좌 화면은 `api/account-api.ts`를 통해 서버 응답을 표시합니다. 주문 상태·체결 내역·조회 정보는 후속 API 연동 시 실제 서비스 응답을 최종 기준으로 맞춰야 합니다.
