# TICK 프론트엔드 목 화면

[`docs/TICK_서비스기획서.md`](../docs/TICK_서비스기획서.md)를 확인하기 위한 화면 초안입니다. 백엔드, 계정, 외부 시세 서비스 없이 실행합니다. React와 TypeScript로 작성했고 Vite로 실행·빌드합니다. 외부 이미지·글꼴이나 CDN이 필요하지 않습니다.

## 실행

Node.js 20.19 이상 또는 22.12 이상을 권장합니다.

```bash
cd frontend
npm install
npm run dev
```

터미널에 표시되는 로컬 주소를 엽니다. 기본 주소는 `http://127.0.0.1:5173`입니다. 다른 프로세스가 포트를 사용하면 Vite가 다른 주소를 안내합니다.

```bash
npm run build
npm run preview
```

`build`는 타입 확인과 정적 파일 생성을 수행합니다. 결과는 `dist`에 만들어집니다. 배포용 빌드도 서버 API 호출 없이 동작합니다. 해시 주소를 사용하므로 화면별 주소를 복사하거나 새로고침할 수 있습니다.

위 대응은 요구사항을 검토할 **화면의 위치**입니다. 거래 정합성, 매칭, 장애 복구, 성능 목표의 구현 또는 검증 완료를 뜻하지 않습니다.

## 확인할 수 있는 상호작용

- 종목 검색, 관심종목 추가·해제, 시세 구독·해제
- 호가 선택 시 주문 가격 입력, 매수·매도 전환, 수량 선택
- 가격·수량 입력 확인, 가용 현금·수량을 이용한 간단한 목 입력 검증
- 주문 확인창을 거쳐 목 주문 목록에 항목 추가
- 주문 입력 하단의 **접수 결과 미리보기**에서 다음 응답을 접수 확정·접수 거절·결과 확인 중으로 선택
- 주문 상세에서 원수량·체결량·취소량·유효 잔량과 여러 체결 내역 확인
- 미체결 잔량 취소 확인과 예약분 해제 예시
- 결과 확인 중 주문의 기존 접수 결과 재확인 예시
- 상단 **목 화면 상태**에서 기본·빈 화면·불러오는 중·오류 상태 전환
- 시세 화면의 **연결 상태 예시**에서 재연결 중·시세 지연 상태 전환
- **초기화**로 시작 데이터 복원

## 계좌 개설과 입출금 사용법

새 **계좌 관리** 화면은 기존 거래용 예시 계좌와 독립된 모의 데이터를 사용합니다. 기존 자산·주문·체결·시세 화면은 계속 사용할 수 있습니다. 새로 개설한 계좌를 주식 주문에 연결하는 기능은 포함하지 않습니다.

1. 왼쪽 메뉴의 **계좌 관리** 또는 `#/accounts`로 이동합니다.
2. **모의 계좌 개설**을 눌러 계좌 이름을 지정합니다. 새 계좌는 **0원**으로 개설됩니다.
3. **입금**을 선택해 금액을 입력하고 확인합니다. 현재 잔고와 입출금 내역에 함께 반영됩니다.
4. **출금**을 선택해 같은 과정을 진행합니다. 잔고를 초과하거나 유효하지 않은 금액을 입력하면 안내됩니다.
5. 내역에서 전체·입금·출금을 구분하고 각 거래 후 잔고를 확인합니다. 거절된 요청은 성공한 입출금 내역에 기록되지 않습니다.
6. 여러 계좌를 만들었다면 상단 선택 계좌를 변경합니다. 계좌별 잔고와 내역은 독립적으로 유지됩니다.

모든 상태는 브라우저 메모리에만 보관합니다. 메뉴 이동으로는 유지되고, 새로고침하거나 상단 **초기화**를 누르면 개설한 계좌와 입출금 내역이 지워집니다. 상단 초기화는 기존 거래용 목 데이터도 처음 상태로 되돌립니다.

### 출금 두 건 요청 시연

- 잔고 0원의 새 계좌에 **1,000,000원**을 입금합니다.
- **동시 출금 요청 시나리오**를 펼칩니다.
- 요청당 금액을 **700,000원**으로 두고 **출금 2건 함께 요청**을 누릅니다.
- 첫 요청은 성공하고 다음 요청은 잔고 부족으로 거절됩니다. 최종 잔고는 **300,000원**이며 성공한 출금 한 건만 내역에 추가됩니다.

이 시연은 브라우저의 최신 상태를 기준으로 대기 중인 요청을 순서대로 반영합니다. 서버 병렬 요청, DB 트랜잭션, 다중 브라우저 간 동시성 보장을 검증한 결과가 아닙니다. 실제 동시성 검증은 계좌 백엔드와 연결한 통합 테스트에서 수행해야 합니다.

### 계좌 목 상태 테스트

```bash
npm test
```

새 계좌의 초기 잔고, 입출금과 내역의 일치, 잘못된 금액 거절, 잔고 초과 출금, 두 건의 출금 요청 처리, 입금 누락 방지, 같은 목 요청의 중복 반영 방지, 계좌 간 격리를 확인합니다. 기존 TypeScript와 Node.js 기본 테스트 실행기를 사용하며 추가 테스트 패키지가 필요하지 않습니다.

상호작용은 현재 브라우저 메모리에서만 동작합니다. 새로고침하면 모든 변경이 초기화됩니다. 로그인, 실제 계좌 권한 검증, 주문 전송, 자동 매칭, 실시간 전송, 데이터 영속화는 연결되어 있지 않습니다. 취소 처리 중 경합이나 응답 재처리 등의 서버 동작도 재현하지 않습니다.

수수료·세금·실제 거래소 호가 단위는 적용하지 않았습니다. 가격, 거래량, 차트, 운영 지표는 모두 예시입니다. 운영 화면의 숫자는 실제 성능 측정 결과가 아닙니다.

## 구조

```text
src/
  components/
    ui.tsx          공통 버튼·표 래퍼·배지·탭·모달·상태 UI
    charts.tsx      외부 라이브러리 없는 예시 SVG 차트
    trading.tsx     주문 표와 주문·취소 상세 화면
  mocks/data.ts     목 데이터와 화면용 타입
  mocks/banking.ts  입출금 계좌의 독립된 목 상태와 잔고·내역 변경 규칙
  pages/            계좌·주문·내역·시세·운영·컴포넌트 화면
  context.tsx       브라우저 메모리에 한정된 목 상태
  banking-context.tsx  새 계좌 개설·선택·입출금 목 상태
  App.tsx           공통 레이아웃과 화면 이동
  styles.css        공통 스타일과 반응형 레이아웃
```

외부 서비스 연동 시 `context.tsx`의 목 동작을 교체하고, `mocks/data.ts`의 화면 데이터 타입에 맞춰 조회 결과를 공급할 수 있습니다. 주문 상태·체결 내역·조회 정보의 최종 기준은 실제 서비스 응답으로 통일해야 합니다.
